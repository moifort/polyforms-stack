# Continuous integration

One workflow per concern, so a red run names its cause and a change touches one file. Templates
in `templates/.github/workflows/`.

| Workflow | Trigger | What it does |
|---|---|---|
| `test-unit`, `test-int`, `test-feat` | push, pull request | One test family each, run separately on purpose |
| `schema` | push, pull request | Schema compatibility against `{{MAIN_BRANCH}}`: a removal without a prior deprecation fails |
| `build-ios` | push touching `ios/**` or the schema | Builds the app, runs the unit test target, the strings catalogue check and the pure-components check; on `{{MAIN_BRANCH}}`, also produces the signed archive and keeps it as a short-lived artifact |
| `deploy` | push to `{{MAIN_BRANCH}}`; pull request labelled `staging` | Build, `terraform apply`, migrations; to production from the branch, to staging from a labelled pull request; `paths-ignore` for prose |
| `testflight-ios` | nightly, manual | The nightly: takes the archive `build-ios` produced for the latest green commit of `{{MAIN_BRANCH}}` (no second build), uploads it once a night when `{{MAIN_BRANCH}}` moved since the last upload, to the internal group, then to the external group through Beta App Review, under the version under development read from the changelog |
| `release-ios` | tag `{{RELEASE_TAG_PATTERN}}` | Version guard against the changelog, panels upload, submission, source maps |
| `pages` | push touching `site/` | Publishes the site |
| `renovate` | nightly, manual | Self-hosted Renovate with its own token |

## Rules

- The build number is the run number. The marketing version is read from the project.
- `paths-ignore` on deploy, schema and the tests for `site/**`, `docs/**`, `screenshots/**`,
  `README.md`, `CLAUDE.md`; never for the served changelogs.
- A workflow authenticates to Google Cloud through Workload Identity Federation, never a key file.
- Secrets are repository secrets; configuration that is not secret (a billing table, an analytics
  property) is a repository variable.
- The iOS archive signs manually with the certificate and profile stored as secrets; the store API
  key uploads and submits.
- **One build per commit.** The app is compiled once per commit of `{{MAIN_BRANCH}}`, by
  `build-ios`, as the archive; the nightly uploads that artifact and runs no macOS job of its
  own. Only the release workflow archives again, on its tag. (Shiori still builds twice today:
  this is a migration of the package.)
- A failing lint or test in CI is a process failure: it should have been caught before the push
  ([04-push.md](04-push.md)).
